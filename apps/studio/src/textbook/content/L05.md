# 一百座房子：把一段做法收成函数

> 从复制粘贴到命名复用，理解函数、参数、返回值与作用域

## 0 本章要解决的问题

村东的空地上画好了五块地基，五户人家等着入冬前搬进来。每块地的位置不同，屋顶样式也不同：三块用橡木，一块用云杉，一块用砖。任务要求每块地都立起一栋能住人的房子：3×3 的地基、一圈墙、3×3 的屋顶、门、床、窗、火把，一样不能少。最后五块门牌由玩家亲手挂到门口。

如果沿用前四章学到的写法，程序会变成一大段复制粘贴。一栋房子光摆方块就要二十多次调用，五栋就是一百多次；每一次调用都要写清楚坐标，而坐标又随地块变化。抄到第三栋时手指记住了顺序，脑子开始走神；抄到第五栋时，某一行少写一个 `+1`，整栋房子就歪了。更糟的是修改：把床从房间北侧挪到南侧，得在五处一模一样的位置各改一遍，漏掉一处，验收时才发现。

循环能解决一部分问题：五块地可以遍历，每块地处理一次。但循环解决不了「一栋房子内部怎么做」的问题。一栋房子包含地基、墙、屋顶、门窗好几个步骤，这些步骤在每一块地上都一样，只是坐标与材料不同。用循环遍历五块地，循环体里还是要写二十多行摆方块的代码；这二十多行与另一栋房子的二十多行没有共享，改一处仍然要改五遍。

问题出在抽象的层级上。「五块地」是数据层面的重复，用循环解决；「一栋房子的造法」是过程层面的重复，需要另一种抽象：把一段步骤收起来，给它一个名字，到需要时用名字执行一次。这个抽象就是函数（function）。

本章要解决的问题因此有两层：命名与参数化。命名是把「造一栋房子」这段步骤写进一个带名字的盒子里；参数化是把「每次不一样的东西」变成参数（parameter），调用时再传进去。两层合起来，才能做到「同一份造房写法造出五栋不同的房子」。

先看一段复制粘贴的起点。下面是一栋房子的地基部分，九次调用只做一件事：在 3×3 的区域里摆圆石。五栋房子就要写五遍这样的九行。

```ts caption:[错误示例] 复制粘贴的起点：地基九行
golem.place("cobblestone", 0, 63, 0)
golem.place("cobblestone", 1, 63, 0)
golem.place("cobblestone", 2, 63, 0)
golem.place("cobblestone", 0, 63, 1)
golem.place("cobblestone", 1, 63, 1)
golem.place("cobblestone", 2, 63, 1)
golem.place("cobblestone", 0, 63, 2)
golem.place("cobblestone", 1, 63, 2)
golem.place("cobblestone", 2, 63, 2)
```

运行后世界会看到：第一块地的地基铺好了。但这段程序只对「原点在 (0,0)」这一块地成立；换到 (12,0) 就要把九个坐标全部改一遍，换到 (0,14) 又要改一遍。九行变成四十五行，改动点变成四十五处。复制粘贴把「一处错误」放大成「五处都要同步修改」，这是本章要消除的负担。

## 1 直觉：把步骤装进带名字的盒子

函数（function）的直觉可以借用生活中的「做法」：菜谱、工序、配方。一道菜的菜谱本身不是饭，它是一段可以照着做的步骤；同一个人可以做很多次，不同的人也可以照着做。菜谱有名字，比如「番茄炒蛋」；你不需要每次都从头描述步骤，只要说「做一份番茄炒蛋」。

函数就是程序里的菜谱。定义（definition）一段函数，相当于写下一份带名字的做法；调用（call）一次函数，相当于让程序照着这份做法执行一遍。定义不等于执行：写下「番茄炒蛋」的菜谱不会让厨房里出现一盘菜；只有真的开火照着做，菜才会出现。同理，定义函数时程序不会执行函数体，只有调用时才会。

菜谱的第二个启发是「份量」与「口味」的区别。菜谱里有些东西是固定的：先炒蛋、再炒番茄、最后合在一起炒；有些东西是每次可以变的：做几人份、放不放糖、用哪种番茄。函数把固定的部分留在函数体里，把变化的部分做成参数。调用时，实参（argument，实际写进去的值）告诉这一次要按哪种变化来做。

这个区分就是「泛化」（generalization）的核心。写函数时最有用的一问是：哪些东西每次使用中不变，哪些会变？不变的写进函数体，变化的做参数。造房子的例子里，不变的是地基、墙、屋顶、门窗的布局规则；变化的是地块原点坐标与屋顶材料。把变化的三样东西做成参数（x、z、style），函数就能适配任意一块地。

函数带来的第一个好处是「改一处，全部生效」。床的位置要挪动，只需要改函数体里那一行，五栋房子一起变。第二个好处是「意图可读」：调用处写 `buildHut(plot.x, plot.z, plot.style)`，读代码的人一眼就知道这一行在造一栋房子，不需要再去读二十行摆方块的细节。第三个好处是「可以检查」：函数体里的逻辑只需要验证一次，五个调用点是同一个逻辑的五个实例，验证一个等于验证全部。

函数也有代价：多了一层间接（读代码要在调用处与函数体之间跳转）、多了参数与作用域的思考、多了命名负担。抽象不是免费午餐，它的回报是复用与可维护。本章的目标不是「把所有代码都塞进函数」，而是在重复出现、有明确边界的地方使用函数。

:::aside 从「复制粘贴」到「过程抽象」
过程抽象（procedural abstraction）指把一组操作打包成一个有名字的过程，隐藏内部细节，只暴露「做什么」与「需要什么」。重复逻辑从「复制」变成「起名字再使用」。函数是它最普遍的形式，也是 λ 演算的核心思想；第 7 章会继续把函数当作值来传递。
:::

## 2 定义与机制

### 2.1 定义与调用：写下做法与照着做

定义函数的写法是 `function 名字(参数列表) { 函数体 }`。`function` 是关键字，名字由你起，括号里是参数列表，花括号里是函数体（函数体是一段语句）。定义语句本身不执行函数体，只是把「这个名字对应这段做法」登记下来。登记发生之后，程序继续执行定义语句后面的语句。

调用函数的写法是 `名字(实参列表)`。程序执行到调用处时，先算出实参的值，再进入函数体，按参数列表把实参绑定给参数，执行函数体，最后回到调用处继续。如果把程序比作一条线，调用像是「跳进函数体走一遍再回来」；定义只是在线旁边放了一份说明，不是一次跳转。

定义与调用的区别可以用一句话检验：定义语句执行时，世界有没有动作？没有，定义只登记名字。调用语句执行时，世界有没有动作？要进函数体看。很多人第一次写函数时的困惑是「我写了函数，为什么世界没变」——因为只定义、没调用。反过来，同一个函数可以调用多次，每次都会执行一遍函数体，世界可能每次都变。

函数名与变量名遵循同一套规则：字母、数字、下划线、美元符号组成，不以数字开头，不用关键字。函数名通常用动词开头，表示「做什么」：`buildHut`（造房子）、`doorOf`（求门的位置）、`wallOf`（求墙的材料）。名字起得清楚，调用处的代码就像一句命令。

### 2.2 参数与实参：每次不同的部分

参数（parameter）是函数定义时写在括号里的占位名，实参（argument）是调用时写进括号的具体值。定义 `function doorOf(x, z) { … }` 里，`x`、`z` 是参数；调用 `doorOf(12, 0)` 时，12 与 0 是实参。调用发生的那一刻，参数与实参按位置对应：第一个实参给第一个参数，第二个给第二个，顺序不能错。

参数的本质是「函数体里可以使用的局部名字，值由调用者提供」。函数体里写 `x + 1`，用的是这次调用传进来的 x；同一个函数被不同调用触发时，x 的值不同，函数体的行为也随之不同。这个机制让函数从「固定做法」变成「适配不同数据的做法」，也就是前面说的泛化。

缺参数时要特别小心。调用 `doorOf(12)` 时，z 没有对应的实参，它的值是 `undefined`，函数体里 `z + 2` 得到 `NaN`，返回的坐标里出现坏值。这类错误不会在定义时报出来，只会在调用后表现为奇怪的结果。检查方法：数一数定义处有几个参数、每个调用处传了几个实参，数量与顺序都要对。

参数传递的是「值」，不是变量本身。调用 `doorOf(a.x, a.z)` 时，函数拿到的是 `a.x` 与 `a.z` 此刻的数值；函数内部修改参数，不会改变外面的 `a.x`。这个规则叫按值传递（pass by value），它让函数内部的修改与外部世界隔离开：函数可以放心使用参数，不必担心改坏调用者的数据。第 7 章闭包会讨论另一种情况，本章先记住这个基本规则。

### 2.3 返回值：把结果交回调用处

函数体执行完会「返回」一个值，写法是 `return 表达式`。执行到 `return` 时，函数立刻结束，表达式的值成为这次调用的结果，回到调用处；调用处可以把这个结果存进变量、继续参与计算，或者直接作为另一个调用的实参。没有写 `return` 的函数返回 `undefined`，表示「没有结果」。

返回值让函数从「做一件事」升级为「算出一个结果」。`doorOf(x, z)` 不摆方块、不移动灰崽，只计算门的位置并返回一个坐标数组；调用者拿到这个数组，再用它做后续动作。这种「函数只负责计算、调用者负责使用」的分工很常见，它让函数更容易测试：给定输入，检查输出，不需要世界参与。

`return` 还有一个容易忽略的性质：它会立刻结束函数。写在 `return` 之后的语句不会执行。如果函数里有分支，每个分支都可以有自己的 `return`；程序执行到哪一个 `return`，就带着哪个值回去。读函数时要顺着分支看返回路径，确认每条路径都返回了合适的值；如果某条路径没有 `return`，那条路径的结果就是 `undefined`。

返回多个结果时，可以用数组打包。数组（array）是按顺序排好的一组值，写法是方括号里用逗号分隔，例如 `[x + 1, 64, z + 2]`；读取时用下标，`door[0]` 是第一个值，`door[2]` 是第三个值。本章的 `doorOf` 返回一个三元组 `[横坐标, 高度, 前后坐标]`，调用者可以按需取用。数组还能保存一串同类数据，比如五块地的数据就是一个数组，用下标与 `.length` 遍历。

### 2.4 局部变量与作用域：函数内部的临时世界

函数体里可以声明变量，例如 `const door = [x + 1, 64, z + 2]`。这些变量是局部变量（local variable）：它们只在函数体内部存在，函数返回后消失，函数外部读不到。参数也是局部变量：`x`、`z` 只在函数内部有意义，外部没有这两个名字。

这个性质叫作用域（scope）：一个名字在程序里的有效范围。函数体内部声明的名字，作用域限于函数体；函数外部声明的名字，函数内部可以读（在更大范围里可见），但函数内部声明的名字不会泄漏到外部。作用域界定了名字的边界，因此函数内部的临时变量不会污染外部，函数之间也不会因为用了同名变量而互相干扰。

作用域还有一个实用价值：函数内部的变量名可以简单。`doorOf` 里用 `door` 这个短名字，不会与外部任何名字冲突；如果它泄漏到外部，五个函数都用 `door` 就会打架。作用域让每个函数拥有自己的小世界，内部怎么命名是函数自己的事，外部只需要关心「传什么进去、返回什么出来」。这个「信息隐藏」的思想后面会反复出现，第 8 章的接口就是它的进一步形式。

函数内部也可以读外部的变量，但本章的程序尽量显式传参：函数需要什么，就从参数传进去。显式传参让函数更容易复用与测试——换一个程序，只要传同样的参数就能工作；依赖外部变量则会把函数与那段代码绑死。

### 2.5 分解与参数化：怎么把一段代码变成函数

把重复代码改写成函数，分两步。第一步是分解（decomposition）：把一大段步骤拆成有名字的小步骤，每个小步骤做一件完整的事。造一栋房子可以拆成：算墙材料、算屋顶材料、铺地基与屋顶、砌墙、装门窗床火把、返回门的位置。每一小步都能单独命名，读的人按名字就能理解整体结构。

第二步是参数化（parameterization）：找出这些小步骤里「每次调用会变」的东西，做成参数。以造房为例，变的是地块原点 (x, z) 与风格 style；不变的是布局规则。参数化之后，`buildHut(x, z, style)` 就成了一个通用做法。判断某个东西该不该做参数，标准很简单：如果它在多次调用中取值不同，做成参数；如果每次一样，留在函数体里。写在函数体里的常量，代表这个做法的固定规则；做成参数的值，代表这次使用的具体材料。

分解与参数化的顺序可以互换，但都要做。只分解不参数化，函数仍然写死某块地，换个地块就错；只参数化不分解，函数会变得又长又杂，参数列表一大串，读的人不知道哪些参数配哪段逻辑。好的函数通常既短又清楚：短到可以在一屏内读完，参数列表三五个以内，函数体里每一步都能用一句话说明。

函数也不是越多越好。只做一次、没有复用价值的三行代码抽成函数，会增加跳转与命名负担；一段逻辑拆成十个只有一行的函数，读起来反而更难。抽函数的时机是：同一段步骤出现第二次，或者一段步骤已经有明确名字与边界。本章五栋房子是五份实例，抽函数的收益很明显；如果只有一栋，直接写更快。

### 2.6 数组速成：按位置取用的一组值

数组（array）是按顺序排列的一组值。写法是方括号里用逗号分隔：`[x + 1, 64, z + 2]`。每个值有一个下标（index），从 0 开始：`door[0]` 是第一个，`door[2]` 是第三个。下标写在方括号里，读出对应位置的值。

数组有两个常用属性与方法。`.length` 读出数组里有多少个值；本章的主程序用 `plots.length` 得到地块数量，而不把「5」写死。`.push(值)` 把一个值追加到数组末尾，数组长度随之加一；需要动态收集结果时用它。这两个操作在后面的章节会经常出现，本章先掌握基本用法。

数组可以嵌套：外层数组的每个元素又是数组，例如 `plans[i][0]` 先取第 i 个计划，再取第一个值。这种结构适合表示「多条记录，每条记录有多个字段」；第 6 章会把它升级成记录与联合类型，让字段有名字、有检查。

数组与函数配合得很好。函数可以返回一个数组，把多个结果打包带回；函数也可以接收数组，对其中每一项做同样的处理。本章的 `doorOf` 返回坐标数组，主程序的循环用 `door[0]`、`door[2]` 取出横坐标与前后坐标；下一章的记录会让这份代码更可读，但结构是同一个结构。

:::warn 常见误解：定义了函数就等于执行了它
有人写完 `function buildHut(x, z, style) { … }` 就点运行，发现世界没有变化，以为函数写错了。定义只是登记「以后听到这个名字就这么做」，不会执行函数体；要让世界变化，必须在定义之后调用它。检查方法：找一找程序里有没有 `buildHut(...)` 这样的调用；只有定义没有调用，函数体里写得再对也不会运行。反过来，调用写在定义之前也会失败：函数名要先登记，才能被调用。
:::

## 3 语法与示例

### 3.1 第一个函数：定义、参数、返回

从最小的函数开始：根据地块位置算出门口的位置，并返回坐标数组。这个函数不碰世界，只做计算。

```ts caption:[照抄] doorOf：参数进来，坐标出去
function doorOf(x, z) {
  const door = [x + 1, 64, z + 2]
  return door
}
const first = world.vars.plots[0]
const door = doorOf(first.x, first.z)
golem.moveTo(door[0], door[2])
```

运行后世界会看到：灰崽走到第一块地门口的位置站好。函数 `doorOf` 被调用了一次，参数 x 得到 `first.x`，参数 z 得到 `first.z`，函数体算出 `[x + 1, 64, z + 2]` 并返回；调用处把返回值存进 `door`，再用下标取出横坐标与前后坐标。

逐行读这段程序。第一行是定义：`function doorOf(x, z)` 声明函数名与两个参数，花括号里是函数体。第二行在函数体内部声明局部变量 `door` 并让它绑定一个数组。第三行 `return door` 结束函数，把数组交回调用处。第四行 `const first = world.vars.plots[0]` 取第一块地的数据。第五行调用函数，把两个实参传进去，返回值存进 `door`。第六行用返回值移动。

这里有一个作用域细节：函数体里的 `door` 与外面的 `door` 是两个不同作用域的变量，只是名字恰好相同。函数体里那行 `return door` 返回的是内部的局部变量；外部 `const door = doorOf(...)` 声明的是另一个变量，绑定返回值。名字相同不影响正确性，但初学时会读混；把内部变量改名为 `position` 会更清楚。这个例子故意用了同名，是为了说明作用域把两个名字隔开：它们各自属于各自的函数体或顶层，互不干扰。

### 3.2 按风格选材料：带分支的函数

墙与屋顶的材料随地块风格变化。把「风格到材料」的映射写成函数，函数体里用分支判断，每个分支 `return` 一种材料。

```ts caption:[照抄] wallOf：同一个问题，三种答案
function wallOf(style) {
  if (style === "spruce") {
    return "spruce_planks"
  }
  if (style === "brick") {
    return "bricks"
  }
  return "oak_planks"
}
```

运行后世界会看到：定义本身不改变世界。等到被调用时，传入 `"oak"` 返回圆石以外的橡木板，传入 `"spruce"` 返回云杉木板，传入 `"brick"` 返回砖块；传入 `"oak"` 时两个 `if` 都不命中，执行最后的 `return`。

这个函数演示了三条 `return` 路径。函数执行时从上往下检查：`style === "spruce"` 命中就返回云杉，函数立刻结束；不命中继续检查 `brick`；两个都不命中，执行最后的 `return "oak_planks"`。最后的 `return` 同时充当兜底：未知风格也返回橡木，不会出现没有返回值的情况。

`if` 与 `return` 的配合有一个规律：一旦某个分支 `return`，后面就不用再写 `else`，因为函数已经结束了。这种写法叫提前返回（early return），可以让嵌套变浅。本章的 `wallOf` 用两个独立的 `if` 加一个最后的 `return`。标准只有一个：每条执行路径都要有一个明确的返回值。

屋顶材料的函数与墙类似，只是返回的方块名不同：云杉屋顶用 `spruce_slab`，砖屋顶用 `stone_brick_slab`，默认用 `oak_slab`。把两个函数放在一起，`buildHut` 就可以只关心布局，不必关心材料细节。

### 3.3 造一栋房：把布局写进函数体

现在写主函数。它接收三个参数：地块原点的 x、z 与风格 style；函数体里先算出墙与屋顶材料，再按布局摆满所有方块，最后返回门的位置。

```ts caption:[照抄] buildHut：一栋房子的完整造法
function buildHut(x, z, style) {
  const wall = wallOf(style)
  const roof = roofOf(style)
  for (let dx = 0; dx < 3; dx = dx + 1) {
    for (let dz = 0; dz < 3; dz = dz + 1) {
      golem.place("cobblestone", x + dx, 63, z + dz)
      golem.place(roof, x + dx, 65, z + dz)
    }
  }
  golem.place(wall, x, 64, z)
  golem.place(wall, x + 1, 64, z)
  golem.place(wall, x + 2, 64, z)
  golem.place(wall, x, 64, z + 1)
  golem.place(wall, x + 2, 64, z + 1)
  golem.place(wall, x, 64, z + 2)
  golem.place(wall, x + 2, 64, z + 2)
  golem.place("oak_door", x + 1, 64, z + 2)
  golem.place("red_bed", x + 1, 64, z)
  golem.place("glass_pane", x, 64, z + 1)
  golem.place("torch", x + 2, 64, z + 1)
  return doorOf(x, z)
}
```

运行后世界会看到：调用一次 `buildHut(x, z, style)`，目标地块上就会出现一栋完整的房子：地基、屋顶、墙、门、床、窗、火把全部就位；函数返回门的位置。

读这个函数，先找参数与局部变量。参数是 x、z、style；局部变量是 wall、roof。函数体里的常量 3、63、64、65 表示布局规则：房子 3×3，地基在 63 层，墙在 64 层，屋顶在 65 层。这些数字对一个村子的房子是固定的，所以留在函数体里，不做参数；如果将来要盖两层楼，再把层数做成参数。

再找循环与顺序。双循环铺地基与屋顶，两个 3×3 区域一次铺完；接着七行砌墙，把门的位置空出来；然后依次放门、床、窗、火把；最后返回门的位置。注意门的位置 `(x + 1, 64, z + 2)` 本来也是墙的一格，程序没有在那一格砌墙，直接放门，避免「先砌墙再放门」时门放不进去。这个细节说明：函数体里的顺序与布局规则必须自洽，不能只照着参考解的顺序抄。

以 `buildHut(12, 0, "spruce")` 为例，可以把执行过程跟踪成一张清单。

1. 进入函数：x = 12，z = 0，style = "spruce"；wall = "spruce_planks"，roof = "spruce_slab"。
2. 双循环在 y=63 铺 3×3 圆石地基，在 y=65 铺 3×3 云杉台阶屋顶。
3. 七格墙与一格门落在 y=64，门在 (13, 64, 2)。
4. 床、窗、火把各就位，分别在 (13, 64, 0)、(12, 64, 1)、(14, 64, 1)。
5. `return doorOf(12, 0)` 返回 `[13, 64, 2]`；调用者用 `door[0]`、`door[2]` 走到门口。

清单里的每个坐标都由参数推出，没有写死。把参数换成另一块地，清单结构不变、坐标整体平移。

最后看返回值。`return doorOf(x, z)` 调用了另一个函数，把它的返回值直接作为自己的返回值。这是一种组合：`buildHut` 负责摆方块，`doorOf` 负责算门的位置，后者被前者复用，调用者也就不必自己再算一遍门。函数的返回值可以是另一个函数调用，这是函数组合的雏形，第 7、8 章会把这种组合做得更系统。

### 3.4 主程序：五块地各调用一次

有了 `buildHut`，主程序只剩几行：遍历地块，取每块地的数据，调用函数，接住返回值。下面这段程序对 `world.vars.plots` 里的每一块地造一栋房，并走到门口。

```ts caption:[照抄] 主程序：循环遍历地块，函数负责造房
const plots = world.vars.plots
for (let i = 0; i < plots.length; i = i + 1) {
  const plot = plots[i]
  golem.moveTo(plot.x + 1, plot.z + 6)
  golem.moveTo(plot.x + 1, plot.z + 3)
  const door = buildHut(plot.x, plot.z, plot.style)
  golem.moveTo(door[0], door[2])
}
golem.moveTo(eira)
golem.say("五栋房子都立起来了")
```

运行后世界会看到：对每一块地，灰崽先走到地块外侧，再依次摆出地基、屋顶、墙、门窗火把，造完走上门口，然后去下一块地。五块地全部造完后，灰崽回到艾拉身边报一句。循环次数由 `plots.length` 决定，程序不用改。

这段程序里「接住返回值」这一步值得说清。`const door = buildHut(...)` 把返回的数组存进 door；`golem.moveTo(door[0], door[2])` 用下标移动。若 `buildHut` 忘了 `return`，`door` 就是 `undefined`，访问 `door[0]` 马上报错。返回值不是装饰，调用者真的会用它。

循环变量 i 的下标从 0 到 `plots.length - 1`，与前面章节的循环规则一致。`const plot = plots[i]` 按当前下标取出地块数据；`plot.x`、`plot.z`、`plot.style` 分别是这块地的原点与风格。注意函数体的参数是三个数字与字符串，而不是整块地对象：`buildHut(plot.x, plot.z, plot.style)` 传的是具体值。这样函数不依赖地块数据的结构，只依赖三个值，复用范围更大；如果以后数据里多了字段，函数不需要改。

### 3.5 定义与调用的对照实验

下面这段程序故意只定义、不调用，用来观察「定义不等于执行」。

```ts caption:[错误示例] 只定义不调用：世界不会变化
function describe(style) {
  golem.say("这栋房子的屋顶样式是 " + style)
}
// 下面这一行被注释掉，函数体不会执行
// describe("oak")
```

运行后世界会看到：什么也没有发生。`describe` 被定义，但没有调用，函数体里的 `say` 一次也没有执行。把注释去掉、改成 `describe("oak")`，灰崽就会说出一句话。这个实验很小，却抓住了函数最容易被误解的一点：定义是「登记做法」，调用才是「照着做」。

调用写在定义之前也会失败。程序按顺序执行，函数名要在调用之前登记；如果先写 `describe("oak")` 再写定义，运行时报「未定义」。把定义集中放在程序开头、调用放在后面，是最稳妥的组织方式；同一段程序里，定义的先后顺序也要注意：`buildHut` 的函数体调用了 `wallOf`、`roofOf`、`doorOf`，这些函数必须在 `buildHut` 被调用之前定义好。

### 3.6 数组：保存与读取多个结果

最后的语法点是数组的基本操作。本章用它来返回门的位置、遍历地块，下面这段程序把三个操作放在一起演示。

```ts caption:[照抄] 数组：字面量、下标、length 与 push
const door = [1, 64, 3]
golem.moveTo(door[0], door[2])
const names = []
names.push("一号房")
names.push("二号房")
golem.say("已经想好了 " + names.length + " 栋房子的名字")
```

运行后世界会看到：灰崽走到 (1, 3) 位置；然后说出「已经想好了 2 栋房子的名字」。数组 `door` 用字面量创建，下标 `[0]`、`[2]` 取值；`names` 先创建空数组，再用 `.push` 追加两个名字，`.length` 读出长度 2。

下标从 0 开始，与循环一致。三个值依次是 `door[0]`、`door[1]`、`door[2]`；写 `door[3]` 会得到 `undefined`，不会报错，但后续用它计算就会出问题。读数组时先确认长度，再确认下标；门的位置这种三元组，索引写错一格就会把高度当横坐标。

数组与对象不同：数组按位置取用，适合一串同类的值；对象按字段取用，适合一条有名字的数据。本章的 `world.vars.plots` 是数组，每个元素是一条地块数据；门的位置用数组表示，因为三个数按顺序排列。第 6 章会把这两种结构都讲清楚，并引入字段有名字、类别可检查的记录类型。

:::tip 抽函数前先找「变」与「不变」
把一段重复代码改写成函数之前，先在纸上分两栏：左边写「每次调用都变的东西」（位置、颜色、数量），右边写「每次都一样的步骤」（顺序、布局、判断）。左边的每一项做成参数，右边的每一步写进函数体。分完两栏，函数的签名与结构就出来了，剩下的只是把代码搬进花括号，把写死的地方换成参数名。
:::

## 4 常见错误

### 错误一：只定义函数，没有调用

现象：运行后世界没有变化，也没有报错。原因：程序里只有 `function` 定义，没有调用语句；定义只是登记，不会执行函数体。改法：在定义之后写调用，例如 `buildHut(plot.x, plot.z, plot.style)`；检查程序里每个函数名是否至少出现在一次调用中，被调用到的函数是否在调用前已经定义。

### 错误二：调用时参数没传、少传或顺序传错

现象：坐标变成 `NaN`、房子盖到错误位置，或者程序直接报错。原因：定义处声明了三个参数，调用处只传了两个，缺的参数是 `undefined`；或者参数顺序传反，把风格传给了 x。改法：对照定义数一遍参数个数与顺序；调用处的实参顺序与定义处一一对应。参数多于三个时，可以考虑把数据打包成记录（第 6 章），减少顺序出错的概率。

### 错误三：忘记 `return`，或者 `return` 写错位置

现象：调用者拿到的结果是 `undefined`，后续访问下标或参与计算时报错。原因：函数体里只计算了结果，没有用 `return` 交回；或者 `return` 写在了某个分支里，有些路径没有返回值。改法：函数体末尾补上 `return 结果`；有分支时检查每条路径都有返回值；调用处如果要用返回值，先确认函数真的返回了它。

### 错误四：函数里把地块坐标写死

现象：五栋房子里只有一栋在正确位置，其余四栋叠在同一块地上，或者盖到了空地外。原因：函数体里直接写 `0`、`12` 之类的具体坐标，没有使用参数 x、z；换一个地块调用，函数仍然在写死的位置施工。改法：函数体里所有坐标都用参数推导，例如 `x + 1`、`z + 2`，不出现与具体地块绑定的数字；把函数拿给另一块地调用，应该自动适配。

### 错误五：在函数外面使用函数内部的局部变量

现象：报错「名字未定义」，或者读到了错误的值。原因：在函数体里用 `const`、`let` 声明的变量作用域仅限函数体，函数返回后外部读不到；试图在调用之后使用它，程序找不到这个名字。改法：需要外部使用的值通过 `return` 返回；不需要外部使用的临时变量就留在函数里，不要依赖它。检查方法：把函数体当成一个黑盒，只看参数与返回值，外部代码不应该依赖盒内的名字。

### 错误六：把函数写成「只做一点点」的碎片

现象：程序能跑，但读起来要不停跳转：每隔两行就调用一个只有一行代码的函数，整体意图更难看清。原因：抽函数的时机判断错了，把只出现一次、没有独立含义的语句也抽成函数。改法：按「同一段步骤出现第二次，或者一段步骤有明确名字与边界」的标准抽函数；拆得太碎的考虑合并回调用处。

## 5 与关卡的关系

L05 的主任务是用同一份造房写法造出五栋房子，每栋门口挂一块门牌。五块地在位置、风格上不同，验收还会换一组地块与风格。任务的三条目标分别对应本章的三个机制：函数复用、参数化、返回值；玩家节拍负责门牌。

第一条目标「五块地各立起一栋能住的房子」检查函数的复用。参考解把一栋房子的布局写进 `hutPlan`（或本章的 `buildHut`），对五块地各调用一次；验收还会看每栋的墙与屋顶材料是否跟着地块风格走。把布局复制五份，改材料就要改五处；只用一份函数，传不同 style 就自动变。

第二条目标「每栋的墙和屋顶按地块样式走」检查参数化。风格来自 `world.vars.plots[i].style`，程序把它作为参数传进函数；函数内部用 `wallOf`、`roofOf` 这类小函数把风格映射成材料名。这条目标检验的正是「函数体里不写死数据」：把风格写死成橡木的程序，遇到云杉或砖地块就会失败。

第三条目标「五块门牌由你亲手挂到门口」是玩家节拍。代码把灰崽送到门口之后，玩家走到每块地的门口，手持门牌按右键挂上。这一步不由函数完成：函数可以计算门牌的位置，却不能替玩家完成「挂门牌」这个动作。任务结构再次提醒读者：程序负责它可以负责的部分，玩家负责只能由人完成的部分。

本关还有两个数据值得注意。第一是材料预算 `world.vars.materialBudget`：五栋房子按布局只该摆固定数量的方块，如果函数重复摆同一格、或者把房子盖到地块外，方块数量就会超预算。第二是保护点 `world.vars.protected`：井台附近不允许摆方块，函数里的坐标推导必须保证所有方块都落在地块范围内。验收的隐藏测试会换地块位置与风格，写死坐标或重复摆放的程序都过不了。

新手在这一关常见的卡点是三处：辅助函数写完却忘了在 `buildHut` 里调用；主程序没有接住 `buildHut` 的返回值，门的位置算出来却没用上；函数体里混用了写死坐标，前几栋正常、换到后面几块地就叠在一起。目标面板逐条显示进度，哪一条不勾就去对应函数里找问题。

加练层会把五块地整体挪走、打乱风格，要求主线写法原样复用。它不引入新知识，只检验函数是否真的做到「数据进来、布局出去」：写死坐标必然失败，参数化正确就能跑。

## 6 小结与练习

本章的要点收成六条。

- 函数是一段有名字的做法：定义只是登记，调用才会执行；先定义后调用。
- 参数是定义处的占位名，实参是调用处的具体值，按位置一一对应；变化的部分做参数，不变的部分留在函数体。
- `return` 把结果交回调用处并立刻结束函数；没有返回值的函数得到 `undefined`。
- 局部变量只在函数体内有效，作用域把函数内部的临时世界与外部隔开；需要外部使用的值用 `return` 交回。
- 数组按位置保存一组值，下标从 0 开始；`.length` 读长度，`.push` 追加，嵌套数组可以表示多条记录。
- 分解负责「把大段步骤拆成有名字的小步骤」，参数化负责「把每次变化的部分变成参数」；两步都做到，函数才能复用。

练习不计分，也不需要提交。建议先写伪代码或分栏表，再落到代码。

1. 写一个函数 `doorOf(x, z)`，返回门口坐标 `[x + 1, 64, z + 2]`；再写一段主程序，用 `world.vars.plots[0]` 调用它并让灰崽走到门口。写出调用前后世界的变化。

## 7 延伸

函数的思想在数学与逻辑里都有很深的根。λ 演算用函数定义与函数应用构造整个计算体系：一切计算都可以表示为「定义函数」与「把函数作用到参数上」。程序语言里的函数、方法、闭包，都可以看作 λ 演算的不同工程化形式。理解「函数是把一段计算命名、并把变化的部分参数化」，比记住某个语言的具体语法更重要；换一门语言，语法会变，这个模型不会变。

真实语言里，函数的形态各不相同。Python 用 `def` 定义函数，JavaScript 用 `function` 或箭头函数，Java 把函数放在类里叫方法，Rust 用 `fn`。TypeScript 还能给参数与返回值标注类型，例如把 `function buildHut(x, z, style)` 写成 `function buildHut(x: number, z: number, style: string): number[]`，让编译器在调用时检查参数类型与返回值类型。本课程的运行环境会剥掉类型标注，标注写不写都能运行；把类型当作给人看的说明与给工具检查的约束，是后面几章会逐步用到的写法。

函数也有代价，本章已经见到一部分：多了一层间接、多了参数与作用域的思考、命名变得更难。更深的代价会在第 7、8 章出现：函数可以当作值传递、可以记住创建时的环境、可以组合成管道，抽象层级越高，调试时越需要耐心追踪。抽象要服务于问题：当重复与变化真的存在，函数是解药；为了抽象而抽象，只会让代码更难读。

## 术语

- 函数（function）— 一段有名字、可重复使用的工作；定义后可以按名字调用多次。
- 函数定义（function definition）— 用 `function` 关键字登记「名字对应哪段做法」的语句；定义本身不执行函数体。
- 函数调用（function call）— 写出函数名与实参，请函数执行一次；示例：`buildHut(plot.x, plot.z, plot.style)`。
- 参数（parameter）— 函数定义时写在括号里的占位名，调用时由实参赋值；示例：`function doorOf(x, z)` 里的 `x`、`z`。
- 实参（argument）— 调用时实际写进括号的值，按位置传给对应参数。
- 返回值（return value）— 函数用 `return` 交回调用处的结果；没有 `return` 的函数返回 `undefined`。
- 局部变量（local variable）— 在函数体内部声明、只在该函数内有效的变量。
- 作用域（scope）— 一个名字在程序里有效的范围；函数体内部声明的名字不会泄漏到外部。
- 抽象（abstraction）— 隐藏内部细节、只暴露用途与接口的做法；函数是最常见的抽象形式之一。
- 参数化（parameterization）— 把每次调用会变化的部分做成参数，让同一段逻辑适配不同数据。
- 数组（array）— 按顺序保存一组值的结构，用下标读取，下标从 0 开始；示例：`[x + 1, 64, z + 2]`。
- 下标（index）— 数组里每个值的位置编号，从 0 开始；示例：`door[2]` 读第三个值。
