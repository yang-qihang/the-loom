## 1. 目标体验

App 启动 → **始终进入 L0 主界面**（不恢复上次页面）。

L0 负责四件事的自动检测/启动：

| 卡片 | 含义 | 关键检查 |
|---|---|---|
| 织机 | 真实 engine sidecar | `127.0.0.1:4317` `/api/health` |
| 世界服务端 | Paper + 插件 | `25565` + 插件 RPC `8765` |
| 织偶 | mineflayer bot | `health.bot.connected` |
| 客户端 | Minecraft 客户端 | 窗口/进程 + 可选版本/启动器状态 |

四张卡片全部 `ready` 后，主界面中心的主按钮才启用：

```text
进入工坊
```

点击后进入 L1 关卡墙。L1 提供：

```text
退出游戏 → 红色确认框 → 完整退出：客户端 + Paper + engine + bot + 桌面壳
```

## 2. L0 状态机

```text
CHECKING（检测中）
  ├─ MISSING（未安装/未找到启动器）
  ├─ STARTING（启动中，按钮变暗，禁止重复点击）
  ├─ READY
  ├─ NEEDS_ACTION（需要用户处理：安装/登录/路径）
  └─ ERROR（失败，可重试）

allReady = engine.READY && paper.READY && bot.READY && client.READY
enterGame.enabled = allReady
```

状态规则：

- 自动检测 + 自动启动；用户不需要先点一堆按钮。
- 启动中：卡片按钮 disabled，显示“正在启动…”，全局启动锁防重复。
- 失败：卡片保留“重新启动/重试”；错误给出中文原因和下一步。
- 客户端手动关闭：卡片立刻变红，主按钮禁用，卡片出现“一键重新拉起”。
- 所有状态都通过同一个 Rust 后端状态快照返回，避免前端各自轮询不同接口。

### 3.1 L0 主界面


- 四个原有按钮（重新检测/启动织机/启动世界/启动《我的世界》）按用户要求移入对应卡片，形成清晰映射。
- 顶部状态灯保留，作为全局一眼可见的运行状态。
- 中心主按钮是唯一进入 L1 的入口，不再有隐藏的“直接进入”路径。
- “怎么开始”保留，但改为：窗口建议（无边框/窗口化全屏）、Alt+Z、伴玩、并排；不再教用户手动启动服务器。

- 确定后完整退出到桌面，不是返回 L0。

### 3.3 L2 关卡内

现有交互不变。额外处理：

- 检测客户端窗口/进程；如果用户误关客户端：
  - 弹红色阻断窗口：“Minecraft 客户端已关闭，当前关卡进度已保留。”

## 4. 客户端启动器策略（需要调研并实现）

### 4.1 产品边界

Minecraft 客户端是外部应用，不内嵌、不打包游戏本体；桌面壳负责检测、启动、等待窗口、失联恢复。

### 4.2 检测优先级

1. **已经在运行的 Minecraft 窗口/进程**：直接复用，不重复启动。
2. **Prism Launcher**：
   - Windows 常见路径、`%LOCALAPPDATA%`、`%PROGRAMFILES%`、PATH；
   - Linux：flatpak `org.prismlauncher.PrismLauncher`/PATH；
   - 支持配置实例名/ID 和服务器地址。
3. **HMCL**：常见安装/便携目录、PATH；优先作为候选适配器。
4. **PCL2（Plain Craft Launcher）**：常见目录/桌面/用户配置；需要确认其可用命令行能力，不能假设。
5. **官方 Minecraft Launcher**：Program Files/Store 应用；通常只能拉起启动器，快速进服能力有限。
6. **通用 `.minecraft` 版本**：检测 `versions/26.1.2/26.1.2.json`，用正确的 Java、版本和账号启动；这是兜底，不绕过账号认证。
7. **都没有** → 一键安装/引导路径。

### 4.3 适配器接口（设计）

```rust
trait MinecraftLauncherAdapter {
    fn detect(&self) -> DetectResult;
    fn launch(&self, profile: &LaunchProfile) -> LaunchResult;
    fn wait_ready(&self, timeout: Duration) -> ReadyResult;
    fn supports_quick_play(&self) -> bool;
    fn install_launcher(&self) -> InstallResult; // 只安装启动器，不替用户登录
}
```

启动器差异（具体 CLI 在实现前实测确认）：

| 启动器 | 检测 | 启动 | 快速进服 |
|---|---|---|---|
| Prism | 路径/实例 | `--launch <instance>` | 需实测参数 |
| HMCL | 路径/PATH | launcher UI 或版本参数 | 需实测 |
| PCL2 | 路径/配置 | 需实测 CLI | 需实测 |
| 官方 | 路径/Store | 拉起 launcher | 通常不支持无人值守 |
| 直接 `.minecraft` | 版本 JSON | 自行拼 Java 命令 | 可 quickPlay，但需账号/版本正确 |

### 4.4 一键安装路径

可以做到“**一键安装启动器**”，但**不能一键绕过账号/正版验证**：

- 提供官方启动器下载/商店安装入口；
- 提供 Prism/HMCL 等启动器下载/安装入口；
- 安装完成后引导用户登录并创建/选择 26.1.2 实例；
- 用户没有客户端时，至少保证主界面有清晰、可执行的“去安装/去下载”路径，而不是只有一句“没有找到 Prism”。

### 4.5 重复启动保护

- 后端全局 `launch_lock` + 前端 `starting` 状态；
- 启动前检查已有 Minecraft 窗口；
- 启动后最多等待窗口 N 秒，未出现则失败并可重试；
- 不允许并发启动多个客户端/多个 Paper；
- 已有客户端时优先复用，不重复拉起。

## 5. 当前实现问题（供后续任务拆分）

1. 启动自动线程只启动 Paper + engine，不启动客户端。
2. 客户端只有向导按钮 `launch_prism`，进入关卡不触发。
3. Windows 无 Prism 时 `probe_prism` 已报红，但进入按钮仍可点。
4. `launch_prism` 默认 `prismlauncher.exe`，缺少多启动器适配和失败校验。
5. 四个启动按钮分散在底部，与检测卡片没有视觉对应关系。
6. 没有“四灯全绿才可进入”的硬门控。
7. 没有 L1 退出游戏的红色确认和完整关闭流程。
8. 没有客户端丢失后的红色阻断/一键重连。
9. 没有每次启动固定回 L0 的保障。
10. 原文档明确“不内嵌客户端，用户只需装 Minecraft 26.1.2”，没有一键安装游戏本体的承诺；本设计只承诺启动器安装/引导。

## 7. 验收标准（摘要）

- 冷启动必进 L0；四灯未全绿时主按钮不可用。
- 四灯全绿且客户端窗口可见 → 主按钮可点 → 进入 L1。
- 启动中不可重复点击；失败可重试。
- L1 退出游戏 → 红色确认 → 客户端/Paper/engine/bot/壳全部关闭。
- L2 客户端被关 → 红色阻断 → 一键重新启动并连接 → 原进度可继续。
- 无 Prism/启动器时提供可执行的一键安装/引导，而不是静默。
- Windows 与 Linux 流程一致（启动器适配器不同）。
