# 35 — 场景美术 Playbook（并行开发也必须遵守）

> 状态：v1（现行美术规范）｜负责人：Lead｜最后更新：2026-11-01
> 目的：让多关卡场景可以并行摆，但视觉质量、寻路安全、评分真值不互相破坏。
> 上游：docs/19-art-direction.md、docs/20-quality-bar.md、docs/34-mc-visual-verification.md

## 1. 硬规则

1. **只用稳定方块**：地面/植被用 `moss_block`、`azalea`/`flowering_azalea`、花、`hay_block`；**不用** `grass_block`、`oak_leaves`（会在真实服务端衰变/变脏）。
2. **中央寻路走廊净空**：从出生点到目标点的 3 格宽主路，y=groundY 到 y=groundY+3 不得放实心方块（灯笼只能挂高处/墙边）。
3. **装饰不得占评分点**：蛋窝、灯位、钟、门、田块等功能位置不放装饰；评分真值永远由服务端快照/事件判定。
4. **每关色板**（从 docs/19 §5a 派生）：
   - 地：moss_block / coarse dirt（少量）/ 石砖 / 圆石 / 砂砾。
   - 木：橡木、云杉、深色橡木；屋顶用楼梯/台阶，不用整块平台。
   - 光：lantern、campfire、shroomlight（藏在树叶/屋檐下），禁止大面积萤石。
   - 色彩点缀：红/橙/黄羊毛幡、花（罂粟/矢车菊/蒲公英）、干草、木桶、花盆。
5. **密度下限**：每一屏视线内至少 3 类材质 + 2 个暖光源 + 1 个可识别的建筑/地标（房子、风车、钟楼、谷仓、摊位、桥）。
6. **角色可辨认**：灰崽/艾拉/村民必须有名字牌或明显服装色；灯柱目标必须有 1–4 编号（牌子/地面标记，后续实现）。

## 2. SceneKit（content/scenes/scene-kit.ts）

只读库，提供：
- `groundPatch(from, to, y, material)`
- `pathLine(points, y, material)`
- `lampPost(x, z, groundY)`
- `villageHouse(x, z, groundY, style)`
- `tree(x, z, groundY, kind)`
- `fenceLine(from, to, y, gapEvery)`
- `banner(x, y, z, color)`
- `SCENE_PALETTE`

新关卡场景必须优先用这些构件；不要复制粘贴大段重复方块数组。

## 3. 截图与验收（Lead 统一执行）

每关必须提供：
- 真实客户端截图 1 张（主视角，能看到地标 + 角色 + 暖光）存 `evidence/scene-shots/L0X.png`；
- 亮度 mean 0.25–0.75、灰度 std ≥0.12、暗部占比（<0.12 亮度）≤0.55；`qa/scene-quality.mjs` 检查；
- 真实 e2e PASS（reference 3 星 / starter 失败 / digest 与 Mock 一致）；
- 寻路无卡死（真实 run 完成，不能出现「织偶无法走到」）；
- 人工（Lead）按本 playbook 的密度/色板/地标规则 review，不通过就打回。

## 4. 并行协作规则

- 每个 agent 只改自己关卡的 `content/levels/LXX.content.ts` 与测试；`scene-kit.ts`、`plugin/`、`apps/` 只读。
- 不许改评分断言；不许为了让场景通过 e2e 而放宽断言。
- 每关先交「代码 + 本地测试 + 需要 Lead 截图的机位/坐标」；截图由 Lead 在同一台真实客户端上统一拍，避免各自环境不一致。
- 如果某关场景 e2e 变红：先修内容，不修测试。
- 并行批次：L03、L05、L08 先各一人；Lead 验收通过后再放下一批（L04、L06、L09）。

## 6. 质量检查

```bash
node qa/scene-quality.mjs evidence/scene-shots
```

- 先用 `-crop` 裁掉 1600×1000 外框黑边；
- 阈值：mean 0.22–0.82、std ≥0.10、暗部 ≤0.72、饱和度 ≥0.08；不通过就不允许作为「已美化」证据。
- 最终仍以 Lead 真实客户端截图 + 人工（按本 playbook）复核为准，机器只抓「暗/灰/空」。

## 7. 自然色彩（不要「脏的丰富」）

- **像现实世界**：苔绿、土褐、石灰、木色、水蓝、暖橙/火光；颜色来自材质本身，而不是大面积染色。
- **禁止**：粉色草地、荧光紫/绿、霓虹红、整面高饱和羊毛墙、把水/草/石改成不符合直觉的颜色。
- **允许**：小面积花、幡、灯笼、铜锈、红石灯作为点缀；同一屏高饱和色面积不超过约 10%。
- **判断标准**：截图里第一眼能说出「这是苔藓/石头/木头/水/火」，而不是「一块彩色塑料」。

## 8. 真实截图机位（2026-10-31 修订）

- 不要手写关卡坐标：先调插件 `session.status`，取 `regionFrom/regionTo/playerSpawn/agentSpawn/center/groundY`，机位必须落在当前 session 的 `region` 内。
- 推荐机位：`playerSpawn + (0, eyeHeight, +8)`，朝场景中心；或 `center + (0, 6, +14)` 俯视 10–20°。截图前用 `player.teleport` 的 `yaw/pitch` 参数固定朝向。
- 每关截图必须包含：地标、至少 2 处暖光、主路/近景道具；拍完跑 `node qa/scene-quality.mjs evidence/scene-shots`。
- 旧机位/旧竞技场残留是此前「截图空/灰」的主要原因之一；以当前 session 区域为准，不以记忆坐标为准。

## 7b. 反「阴间搭配」（用户红线）

- **禁止反现实组合**：荧光绿/紫、粉草地、霓虹红蓝对撞、随机彩色棋盘墙、整面彩虹羊毛、漂浮无支撑的彩色方块。
- **禁止把颜色当细节**：每种颜色必须有材质/功能理由（木头是木色、石头是石灰、水是蓝、麦是金、火是暖橙）；没有理由就不要加色。
- **结构必须成立**：墙有墙基/屋檐，屋顶有坡度，柱子落地，箱子/桶/工具放在该在的地方；不能靠堆随机方块冒充“丰富”。
- **一屏配色公式**：1 个主色（约 60%）+ 1–2 个自然辅助色（约 30%）+ 1 个小面积点缀（≤10%）。点缀只能是花、幡、灯、铜锈、红石灯这类小物件。
- **一眼判断**：如果画面像“彩色塑料/儿童积木/阴间滤镜”，直接重做；宁可朴素自然，也不要脏的丰富。
- 截图验收时必须正常曝光、白天/黄昏可辨认；过暗、过饱和、颜色互相打架都算不通过。

## 9. 2026-11-01 玩家节拍视觉补充

- 玩家节拍目标不再依赖「台阶/可站立结构」让玩家看见柱顶：目标方块激活后由插件显示发光标记（`loom-beat-marker`），并配 actionbar 提示；场景里不要再为节拍加误导性台阶（L01 的两级石砖台阶已删除）。
- 装饰不得遮挡玩家节拍目标 6 格内的视线路径；发光标记所在格保持可见、不加高饱和装饰。
