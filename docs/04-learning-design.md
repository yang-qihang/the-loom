## 0. TL;DR（8 条）

1. **动机先于语法**：每关开场 ≤90 秒的「失败演示」，让痛点先发生；抽象是止痛药，不是新知识。
2. **世界是老师**：反馈优先用世界内语言（方块、粒子、音效、村民、时间），UI 只做最小补充；这直接呼应 Minecraft 自身的教学方式（recipe book / advancements）。
3. **一关一个抽象（至多两个）**，旧抽象必须复用；用 PriMM 六拍组织，每关结尾有「玩家自己动手」的节拍。
4. **notional machine 必须一致**：织偶「严格照字面执行、没有理解力」——这条设定同时是笑话、是 bug 解释、是调试教学的支点，全 10 关不允许漂移。
5. **失败无惩罚**：无限重试、一键重置、3 次失败自动提示、提示 3 级后自动补一半代码；**没有死局**。
6. **文本极简**：教练单条 ≤45 字、对话 ≤10 条、目标 ≤3 条；术语首现必须配一句人话，并且只在该关出现。
7. **迁移是唯一硬指标**：每关有隐藏的随机化变体；Act 末关和终局要求「同一抽象、换场景」；评估测的是迁移，不是记忆。
8. **可被盲测**：一个只看得到玩家界面的 agent 必须能通关（见 §9）；通不过就改设计，不怪玩家。

## 1. 学习者画像与课程目标

- **画像**：大一/高中；会电脑基本操作；玩过或看过 Minecraft（不是硬核红石玩家）；**多数零编程**；少数会一点 Scratch/Python。
- **非目标**：不培养「能写 App 的人」，不追求算法/工程/性能；目标是**PL 世界观 + 迁移能力 + 不恐惧代码**。
- **课程目标（可测量）**：
  1. 用 14 个核心抽象（A1–A14）的名字与「它解决什么问题」解释陌生代码（选择题 + 口头，≥80%；A0 执行模型不计入「可命名」指标）；
  2. 在没教过的语言片段（Python/Haskell/Rust）中认出这些抽象（迁移测验 ≥80%）；
  3. 独立完成 30 分钟综合任务（终局关或 Lab-T）；
  4. 说出一句「语言设计」层面的判断：语法是皮、抽象是骨、组合优于继承。
- **情感目标**：结束时觉得「编程不是玄学，而是我能理解、能使用、能评价的工具」。

## 2. 教学法基础（理论 → 本项目的落地机制）

| 理论/方法 | 关键结论 | 在游戏里的落地 |
|---|---|---|
| 建构主义（Papert） | 知识在「做东西」中建构 | 每关产出一个可见的世界变化（灯河、房子、桥），不是答题 |
| 认知负荷（Sweller） | 新手工作记忆有限；worked example + fading 有效 | 预填 50–80% 骨架；每关只加 1 个新符号；UI 减少 split-attention（代码与世界同屏） |
| PriMM（Predict-Run-Investigate-Modify-Make） | 先读/预测再改，最后创作 | 每关六拍固定模板（§3） |
| Use-Modify-Create（Lee et al.） | 渐进式参与降低门槛 | L1–L2 Use，L3–L6 Modify，L7+ Create/扩展 |
| Parsons problems | 重排代码比重写更聚焦结构 | 卡关时给「打乱的两行」让学生排序（L4+ 提示形态之一） |
| Notional machine（Sorva） | 新手需要一致的执行模型 | 「织偶严格照字面执行」+ 执行可视化（它会在错误处挠头/停住） |
| 预测-观察-解释（POE） | 预测错误会带来更深学习 | 每关 1–2 道点击式预测题，答错不惩罚、重播演示 |
| 自我决定理论（Deci & Ryan） | 自主/胜任/联结驱动内在动机 | 自主：多解、挑战变体；胜任：明确的小胜利；联结：村民/艾拉/织偶的关系 |
| 生成效应 / 测试效应 | 主动产出比被动看记得牢 | Make 节拍必须学生自己写；每关结尾有回顾问题 |
| 游戏化 meta 分析 | 积分/徽章本身效果弱，**反馈与进度可视化**有效 | 不用积分排行榜；用 advancement、符文图鉴、世界状态变化做反馈 |
| 迁移（transfer） | 变式练习 + 跨情境应用 | 隐藏测试随机化；Act 终局换场景复用；Codex 跨语言对照 |

> 引用与证据强度：见 `research/pedagogy-notes.md`；报告中引用时标注来源，不宣称「本游戏提升学习成绩」，只宣称「可玩性 + 抽象覆盖 + 迁移设计」。几个可直接引用的数字：PriMM 在 13 所学校 493 名学生的后测优于对照；游戏化 meta 分析效应量 g≈.25–.49（Sailer & Homner 2020），且 game fiction + 社交互动才调节行为——所以我们做叙事与村民/同伴关系，而不是积分排行榜；严肃游戏学习效应 d≈.29–.36 但动机效应不显著（Wouters 2013），因此动机必须靠设计而不是「游戏」这个标签。

### 2.1 为什么 10 关不是缩水

HRM/7 Billion Humans 是 40–60 个 1–3 分钟的短关；本项目的 10 关是 **10–25 分钟的迷你项目**（每关含 2–3 个子任务、1 个隐藏变体、1 个玩家节拍），加 4 个 Challenge Lab 与 Codex，总学习时长约 2.5–3.5 小时（不含 Labs；含 Labs ≤4 小时），**与短关卡合集的学习时间同量级**，但每关有完整的「动机—实践—迁移」弧线。报告里用这张对照表回答「关数少」的质疑。

## 3. 每关节拍模板（PriMM + 动机 + 玩家节拍）

| 节拍 | 时长 | 玩家在做什么 | 设计要求（spec 必须写） | UI/世界变化 |
|---|---|---|---|---|
| 0 动机刺 | 30–90s | 看艾拉演示一个「没有该抽象」的失败/麻烦 | `painBeat`：必须有情绪、有画面、≤90s | 世界状态恶化（天黑/村民摔倒/机器卡住），不惩罚 |
| 1 Predict | 30–60s | 先猜：这段代码/这个改动会发生什么 | 2 道预测题（单选/排序），答错重播演示。**分级**：L1–L2 只做行为/概念预测（「先写第 3 盏会怎样」），L3 起才预测代码输出——notional machine 未建立时不要考读代码（Sorva 2013） | 高亮代码对应行 |
| 2 Run/See | 1–2min | 跑通给定骨架，看世界变化 | `starterCode` 能跑，且**不改时必须失败**（防止 starter 即答案） | 一个「啊哈」小瞬间 |
| 3 Investigate | 1–2min | 修一个坏代码/处理一个边界 | `investigate`：brokenCode + expectedError + 一句解释 | 错误可视化 + 错误翻译 |
| 4 Modify | 2–4min | 在骨架上改 3–8 行完成主任务 | `mainTask` + `successCriteria` | 目标面板逐条打勾 |
| 5 Make | 2–5min | 去掉部分脚手架，独立写/扩展到新场景 | `makeTask` + `hiddenTests`（随机化） | 新目标出现，隐藏测试只在验收跑 |
| 6 玩家节拍 + 结算 | 30–60s | 玩家自己做一个 MC 操作收尾 | `playerBeat` 必须是可检测的世界动作 | 粒子/音效/advancement/符文解锁 |

**节奏规则**：一个节拍不超过 5 分钟；任何一节拍里如果玩家 90 秒没动作，教练必须给提示（见 §5）；关内不做超过 3 次「读长文」。

## 4. Notional machine：织偶（The Golem）

- **一句话**：织偶没有理解力，只有执行力；你写什么，它做什么；它做错了，是因为你写错了。
- **一致性规则（全课程不得漂移）**：
  1. 织偶不会「猜意图」：少写一个 `moveTo` 它就会直线走向下一目标（可能落水/撞墙）——这既是笑点也是调试素材；
  2. 织偶的动作是**有序**的：Act I–II 的 SDK 写操作按调用顺序入队执行（隐藏 await）；L9 揭示「等待」的真相；
  3. 织偶不会自我修复：出错会「挠头停住」，等待玩家修代码或重置；
  4. 织偶能看到的世界 = SDK 暴露的只读快照（不是全知）；
  5. 评分是「世界是否变对」，不是「织偶是否辛苦」。
- **为什么重要**：新手最大的误解是「计算机应该懂我」；这个 notional machine 用角色性格把「字面执行」变成可感知、可预测、可调侃的设定。所有错误翻译、提示文案、Codex 都引用这套设定。
- **调试教学**：L3 起引入「修复艾拉的旧符文」：故意给坏代码，让学生读错误、定位、改一行；教的是「读代码 + 验证假设」，不是语法。

## 5. 提示系统（Coach / Hint Ladder）

### 5.1 三级提示（全课程统一）

| 级别 | 触发 | 内容规范 | 例子（L1） |
|---|---|---|---|
| L1 nudge | 第 1 次失败 或 90s 无动作 | 只指向「看哪里/想什么」，不给答案 | 「先别看代码，看小径：灰烬现在该去哪一盏？」 |
| L2 technique | 第 2 次失败 | 给方法/结构，不贴代码 | 「`moveTo` 只负责走，`place` 才负责点亮；每盏灯要两句。」 |
| L3 near-solution | 第 3 次失败 或 3 分钟无进展 | 给可照抄的结构/坐标，**不给完整答案** | 「把第一盏的两行复制一遍，只改括号里的坐标：2 号是 (-12, -2)。」 |
| 防死局底线 | L3 后 60s 仍无进展 | 自动填入参考解的**前半段**，保留后半段 | 「艾拉替你写了前半段，后面交给你。」 |

### 5.2 规则

- 提示必须**引用玩家当前代码位置**（`codeAnchor`），不能泛泛而谈；
- 同一条提示不重复弹出；玩家可主动点「提示」按钮，也可关闭自动提示（尊重自主性）；
- 提示不剧透 `wowMoment` 与剧情转折；
- 教练语气：具体、温和、不居高临下、不夸张；禁止「真棒！」式空夸（用具体的「灯亮了，村民能看见路了」替代）；
- 教练有「不知道」的权利：遇到超纲问题，艾拉说「这要等你修好结构之核再讲」，保持世界观一致。

### 5.3 错误翻译（与 §3 语言决策联动）

- 语法错误：阻断运行，高亮行 + 一句人话（「第 3 行少了一个右括号」）；
- 类型错误：不阻断，编辑器内联 + 教练一句（「织典说这里类型不对——它先替你发现了」）；
- 运行时错误：世界内表现（织偶停住/挠头）+ 一句人话 + 「重试」按钮；
- 超时/死循环：观察器给出「织偶跑了太久，先停一下」，不指责、不扣分。

## 6. 失败与挫败管理

- **无惩罚**：不扣分、不掉物品、不锁关卡；失败 = 世界重置 + 一句提示。
- **即时重试**：重置 ≤2 秒；重试不需要重新读剧情。
- **卡住检测**：90 秒无操作 / 3 次同类失败 / 同一行反复修改无进展 → 触发提示梯。
- **可选跳过**：任何关卡的「Make」子任务可跳过（保留主任务），保证推进；跳过记录进 telemetry（用于分析难度）。
- **难度自适应（轻量）**：隐藏测试的随机化范围可随尝试次数收窄（P2；4 天内只做「尝试 ≥5 次后隐藏变体固定为简单档」）。
- **无障碍**：色盲友好配色、字体 ≥16px、可关闭粒子/屏幕震动、键盘操作、中文文案可读性检查（单句 ≤40 字）。
- **情绪曲线**：每关「小挫折 → 小胜利」；每 Act「积累 → 大演出」；禁止连续两关高强度抽象（L6/L8/L9 之间用 L7 做呼吸）。

## 7. 抽象的教学顺序与「代价」教学

顺序依据：**从「看得见的行为」到「看不见的结构」再到「时间与协作」**——先建立「我能让世界动」的掌控感，再讲组织方式，最后讲现代语言最难的异步/并发。每个抽象都要讲**代价**（抽象不是免费的）：

| 抽象 | 引入关卡 | 它解决的问题 | 它的代价（要在 Codex/教练里说） |
|---|---|---|---|
| 顺序/求值 | L1 | 世界按时间发生 | 写得长、难改 |
| 变量 | L2 | 记住中间结果 | 状态多了会乱（为 L10 埋线） |
| 分支 | L3 | 世界有多种情形 | 分支爆炸（为 L6 的 ADT 埋线） |
| 循环 | L4 | 重复执行 | 边界/终止条件容易错 |
| 函数 | L5 | 复用与命名 | 参数与作用域的新负担 |
| 记录/ADT | L6 | 数据成组、互斥情况可穷举 | 多写类型；建模需要思考 |
| 闭包/HOF | L7 | 把行为当数据、控制流与业务分离 | 抽象层数变多，调试不直观 |
| 接口/组合 | L8 | 解耦、可替换、避免继承地狱 | 需要先想清契约；过度抽象的风险 |
| 异步 | L9 | 等待时做别的事 | 执行顺序不再直观（竞态/错误处理） |
| 并发 | L10 | 多执行者协作 | 死锁、竞态、协调成本 |
| 元语言 | EP | 语言本身可被构造 | 抽象层级最高、离应用最远 |

> Codex 每页固定四段：**问题 → 机制 → 代价 → 跨语言对照**。这是「理解抽象」的骨架，也是报告里「教学深度」的证据。

## 8. 常见误解与对策

| 误解 | 表现 | 设计对策 | 出现关卡 |
|---|---|---|---|
| 「程序会理解我的意图」 | 少写指令却期待正确结果 | 织偶字面执行 + 失败可视化 | L1–L2 |
| 「变量 = 数学等式」 | 以为 `x = x + 1` 不成立 | 用「鸡蛋计数器」具象化；动画显示旧值→新值 | L2 |
| 「循环 = 一直做」 | 忘记终止条件 | L4 painBeat：没有终止条件，织偶种到明天 | L4 |
| 「函数 = 写短一点」 | 只把代码搬进函数，不参数化 | L5 隐藏测试换位置/风格 → 不参数化就失败 | L5 |
| 「类型 = 麻烦」 | 讨厌写注解 | 类型后置；编辑器第一条类型错误用「织典先发现了」话术 | L6–L8 |
| 「接口 = 继承」 | 想用 class 继承复用 | L8 继承灾难小剧场 + 注入未见过机器 | L8 |
| 「async = 更快」 | 以为加 async 就并行 | L9 计时对比：顺序 await 反而更慢 | L9 |
| 「并发 = 同时跑就行」 | 抢资源/死锁 | L10 死锁可视化 + 精确预算 | L10 |
| 「抽象越高级越好」 | 过度封装 | Codex「代价」页 + L8 的「不要为了抽象而抽象」 | L8 |

## 9. 盲测验收协议（学习设计的质量门）

**Blind Solver Agent**：只给（a）关卡 UI 里玩家能看到的所有文本（b）当前可用 API 文档（c）编辑器与运行按钮的截图/DOM，**不给 spec、不给参考解、不给隐藏测试**，在沙箱里操作。

| 指标 | 通过标准（P0/P1 关） | 不通过时改什么 |
|---|---|---|
| 完成率 | ≥80% | 改任务描述/提示/梯度，不改断言放水 |
| 时限 | L1–L7 ≤15 min；L8–L10 ≤20 min | 拆子任务/加脚手架 |
| 提示使用 | ≤2 级、≤2 次 | 检查 painBeat 与 Investigate 是否讲清 |
| 卡点 | 记录每个卡住 >2 min 的位置 | 卡点即 spec 歧义，必须修 |
| 新手模拟 | 每关报 ≥3 个「看不懂」，且都能在 spec 的 misconceptions 里找到对策 | 补文案/补演示 |

**Cognitive Walkthrough（人工 10 分钟/关）**：拿着关卡文本问四个问题：①玩家知道现在要干什么吗？②知道怎么开始吗？③做对时能看出来吗？④做错时知道为什么吗？任一答「不确定」→ 修改。

## 10. 评估与学习证据

### 10.1 形成性（游戏内，自动收集）

- 预测题正确率（每关 2 题）；Investigate 修复耗时；Make 是否使用提示；重试次数；错误翻译命中分布。
- 每关结尾「回顾」：1 道「用一句话说这关的符文解决了什么问题」的填空（不计分，进 telemetry，报告引用）。
- Lab-T 的「写断言」本身就是可观察的验证能力证据。

### 10.2 总结性（Demo 日小样本，n=4–6）

- 前测 6 题（抽象识别：给 Python/Haskell/Rust 片段，问「这用到了哪个概念」）；
- 试玩 25 分钟（L1–L3 + 一个自选高级关）；
- 后测 6 题（同构换题）+ SUS-lite 5 题 + 5 问半结构访谈；
- 指标：完成率、平均提示、前后测提升、SUS-lite 分数、定性主题（「原来如此」时刻/卡点/想继续吗）。
- **报告口径**：n 小，只报描述统计与质性证据，**不宣称统计显著**；前测本身有测试效应，前后测差异不能全部归因于游戏（需在局限里写明）；SUS-lite 不是验证量表，只作方向性参考；盲测（agent 通关）不等于学习证据。

### 10.3 Telemetry 事件（最小集）

`level_start / run / error(translated_code) / hint(level) / success_criteria_met(id) / trial_result / reset / player_beat / level_complete / time_spent / code_snapshot(去标识)`。存储本地 JSONL；不上传；匿名 ID。

## 11. 设计风险与迭代规则

| 风险 | 信号 | 迭代规则 |
|---|---|---|
| 场景割裂（「curated 几个 scene」） | 玩家记不住剧情/角色 | 固定角色（艾拉/织偶/村民）+ 世界状态跨关可见（灯亮着、房子在、桥已建）+ Act 结局演出 |
| L6/L8 太抽象劝退 | 盲测失败率 >40% / 提示集中在这两关 | 拆 phase、加重脚手架、类型不阻断、必要时降级为 Lab |
| 文本太多被跳过 | 玩家 >2 秒没读就点继续 | 单条 ≤45 字、每关 ≤10 条、关键信息用世界内标记 |
| 自动化快感被手动节拍打断 | 玩家在 playerBeat 处困惑 | 手动节拍 ≤60 秒、有非语言提示（高亮方块/粒子箭头）、可跳过（P2） |
| 硬核 MC 玩家觉得任务幼稚 | 评论「就这？」 | 隐藏变体 + Challenge Lab + 多解；报告里定位为「入门课，不是 MC 挑战地图」 |
| 评估证据太薄 | 报告只有截图 | Day2 起就收集 telemetry；CP1 就做 2 人 playtest；报告如实写 n 小 |
